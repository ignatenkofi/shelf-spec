# ADR 0006: BYOM — вендорскую память не синхронизируем

## Статус

accepted

## Контекст

У вендоров есть встроенные памяти (ChatGPT memory, Claude-память и т.п.).
Соблазн «переносимости» — синхронизировать их с полкой: выгружать,
загружать, держать в консистентности. Но стабильных публичных API экспорта
нет, семантики несовместимы (их память — внутренние заметки модели о
пользователе; полка — структурированные эпизоды/документы), а
двунаправленный sync — классический источник конфликтов и тихой порчи.

## Решение

**Bring your own memory:** полка не синхронизируется с вендорскими
памятями — она их **заменяет** как первичный носитель. Пользователь ведёт
память на полке; вендорские памяти считаются кэшем удобства конкретного
клиента, не источником правды.

Import-адаптеры (разовый импорт выгрузки вендорской памяти в эпизоды
полки) — допустимы как поздняя фаза (M3), экспорт-адаптеры и live-sync —
вне скоупа.

## Альтернативы

- **Двунаправленный sync.** Нет API, хрупко, семантический мисматч,
  конфликтность. Отклонено.
- **Полка как зеркало вендорской памяти (read-only копия).** Инвертирует
  владение: источником правды остаётся вендор. Противоречит цели проекта.
  Отклонено.

## Последствия

Требуется дисциплина пользователя: память ведётся на полке (у владельца она
уже есть — /shelve-практика). «Переносимость» означает «твоя память всегда
с тобой», а не «мы утащим память из ChatGPT» — это честное обещание,
которое можно сдержать. Разовый импорт при онбординге нового пользователя —
понятная будущая фича, не обязательство ядра.

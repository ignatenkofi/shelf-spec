# ADR 0001: Спек-первичность — формат как продукт, а не ещё один memory-store

## Статус

proposed

## Контекст

«Переносимая память между AI-клиентами» как категория не пуста: mem0 /
OpenMemory MCP прямо позиционируются «память едет с тобой между
MCP-клиентами»; Zep, Letta и др. дают memory-слои для приложений. Все они —
векторные/графовые store'ы: память непрозрачна, не диффается, живёт в их
формате и их рантайме. Транспортную половину задачи (один сервер — много
вендоров) уже решил сам MCP, принятый индустрией.

При этом у владельца есть работающая альтернативная модель памяти:
docshelf/memshelf — markdown в git, человекочитаемо, с политиками и
журналом. Но её формат существует только как де-факто код + CLAUDE.md
конкретных полок — сторонняя реализация невозможна.

## Решение

Продукт openshelf — **спек формата полки** (shelf-spec: раскладка,
frontmatter, INDEX/meta/ledger/POLICY, нормативные правила, режимы
single/multi). Сервер — референс-реализация спека, и это уже существующий
docshelf-mcp. Ценность против store'ов: память, которую можно **прочитать,
продиффать, отревьюить PR-ом и унести clone-ом**; git — одновременно формат
переносимости и механизм конкурентности.

Дом-паттерн подтверждён дважды: `issue-standard.yml` (issue-kit ADR-0002),
`lesson_schema.json` (sqst). Спек версионируется, валидируется схемой,
несовместимый манифест — `config-error` до любой операции.

## Альтернативы

- **Ещё один memory-server (bare).** Лобовая конкуренция с mem0 на их поле,
  без нашего differentiator'а. Отклонено — протухнет.
- **Форк mem0 / надстройка над ним.** Их модель vector-first и
  непрозрачна — ровно то, от чего уходим. Отклонено.
- **Конвенции без спека.** Так уже есть; сторонняя реализация и
  межвендорная совместимость невозможны без контракта. Отклонено.

## Последствия

Формат становится публичным контрактом (semver, bump major на
несовместимое). Нужна дисциплина «спек описателен в v0»: он фиксирует
работающее, а не изобретает. Реализации обязаны проходить `shelf_validate`.
